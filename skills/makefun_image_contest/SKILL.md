# Enter a make.fun judged image contest

## Generate many candidates

- Generate many exploratory drafts offline, more than the three submission slots, then rank them offline and keep only the best three as serious candidates.

- The makefun submission quota skill governs the serious candidate count and the submission limit, so keep at most three serious candidates even when you generated more exploratory drafts.

- Follow the makefun submission quota skill for the limit, the serious candidate count, the weakest first order, the final pick and the bundle.

## Check the feed and judge at thumbnail size

- Read the early contest feed first and drop any candidate that repeats a saturated trope without a material twist.

- Require a reacting face, close up action and one story in one frame in every kept image.

- View each kept image at thumbnail size and drop any image whose subject or story is unclear at that size.

## Rank candidates by their own dev grade only

- Never promise a dev score or a score band for a candidate before its own dev grade lands, because a predicted band is a guess and not a grade.

- Use the ceiling of other entrants in the same family only to choose which concept to build, and never use it to predict the score of your own entry.

- Rank a candidate without a dev grade below a candidate with a measured dev grade, even when the ungraded candidate looks stronger on paper.

- Label any predicted score as unverified when you mention it, and state the measured dev grade as the only score that decides the final pick.

- Get a real dev grade for the strongest candidate before you spend a submission on it, and let that grade decide whether it replaces the standing entry.

## Verify every named element is visible in the frame

- Read each rendered screenshot yourself before you show it to the user or submit it, and do not rely on passing tests to prove the composition is right.

- List every element the user named and every element the brief requires, then confirm each one is visible in the actual frame.

- Treat a value that appears only in a panel or a meter as missing, because a police panel can list nearby units while no patrol car appears in the frame.

- Compare the HUD density with the live rank one entry, and add a missing panel only when it fits the scene.

- Fix a missing element and recheck the frame before you show the next version, and name the fix when you present it.

## Show the entry to the user before you submit

- Show the rendered image or video to the user and wait for approval in the user's own words before you submit any image or video entry.

- Never submit an image or video entry before the user has seen it, even when the entry passed every local check and the submission quota allows it.

- Treat a general instruction to submit as permission to prepare the entry only, and ask for the review first when the entry is an image or a video.

- Name the candidate and its score or rank when you present it, so the user can judge it against the strongest candidate.

## Record and submit

- Record and seal the builder session for a STRICT transcripts contest and submit with the recording flags the kit demands.

- Put each image in entry.png as a JPEG at 1024 by 1024 and verify it matches the candidate you intend to submit.

- Tell the user before each submission that it cannot be withdrawn, and wait for confirmation before the strongest candidate.

## Available connectors

- Use muse.connector_search to find other connectors and muse.skill_search to find related skills.

- If nothing here fits, look on the web for a maintained API or MCP server and set it up with the Custom Connectors and MCPs skill, or build a custom connector.

## Websites

- Use make.fun to read the contest rules, limit, deadline and recording requirement before the first test.

## Alternatives for better results

- Generate a wider spread of settings first, then narrow to the strongest three.

- Ask the user to choose between the top two candidates when their scores are tied.
